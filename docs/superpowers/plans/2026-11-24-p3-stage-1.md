# DevRounds P3 Stage 1 (Conventions Engine) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DevRounds keeps each project's conventions as a versioned document with verified evidence, which agents
propose and only human members approve; renders the active version into fenced blocks of the repo's AGENTS/README
files; checks a change's added lines and new paths against it in a gate, with the generated blocks compared byte for
byte; records every check and measures it per rule; and runs all of it on DevRounds itself, testable without the
Clickmax monorepo.

**Architecture:** `convention_sets` holds immutable versions (`proposed | active | superseded | rejected | withdrawn`),
one active and one open proposal per project. Everything that reads the repo is a CLI command run in the worktree
(`propose --cwd` verifies evidence, `render`, `check`, `verify`, `candidates`); the control plane only stores, diffs,
approves and measures. The checker reads a unified diff (stdin or a file) that the job type produces, fetches the active
version, applies `pattern` and `path` rules to added lines and new paths, renders the active version to detect drift,
prints failures first, posts the result for its run (`DEVROUNDS_RUN_ID`) and exits 1 on a blocking violation.

**Tech Stack:** as P2 (Node ≥24 TypeScript, Fastify 5, TypeBox, Kysely/pg, Postgres 17, `node:test`, Biome 2.6.8,
React for `web/`). No new dependency unless the glob matcher needs one (design §7).

**Spec:** `docs/superpowers/specs/2026-11-24-p3-conventions-design.md` (calls 1-16, §3 data model, §4 surface, §6

## Global Constraints

- Every P1/P2 Global Constraint still holds: `tenant_id uuid not null`, RLS forced through `isolate()`, composite FKs
  `(tenant_id, x_id) -> (tenant_id, id)` with an index each, catalog guards pass without edits, DR201 for
  cross-tenant, codes only in `errors/words.ts` + `pnpm gen:errors`, no sync fs/child-process in `control-plane/src`,
  no vendor/customer/tool name in engine code (`git` appears only in job type fixtures, never in `control-plane/src`),
  signed English commits, `Idempotency-Key` on mutating routes.
- Migrations 0023-0024 in that order on main; renumber to the next free key if a P2 task lands one first.
- New codes: DR310 `Proposal {version} is based on version {basedOn}, but version {active} is active.` (409, keys
  `version, basedOn, active`, hint: export the active version, apply the change, propose again); DR311 `Proposal
  {version} is open for project {project}.` (409, hint: approve or reject it, or propose with `--replace`); DR312 `Run
  {run} is {state}; a check result needs a running run.` (409); DR313 `Conventions version {version} is {state}; only a
  proposed version can be approved or rejected.` (409). New not-found kind `conventions`. Approve and reject by a
  non-human actor: DR453 with action `approve conventions` / `reject conventions`.
- Document limits (design §3): 500 rules, 200 facts, 20 targets, 1-20 evidence per item, excerpt 1-300 chars, keys
  `^[a-z0-9][a-z0-9.-]{0,99}$` unique across rules and facts, regex ≤ 1000 chars compiled with flags from `[imsu]` only
  (no `g`/`y`: `lastIndex` state), document ≤ 1 MB. A `pattern` rule needs `paths` and at least one bad example.
- Check result: at most 500 violations stored per check, `blocking`/`warnings` counts exact; one result per run.
- Cache: the conventions check carries no `cache_key` unless it includes the active `documentSha` (`conventions show
  --json`), so an approval invalidates every cached green.
- Line endings: render and drift compare after normalizing CRLF to LF; `render` writes with the file's existing ending.
- Lint is `rtk proxy pnpm lint`; cargo is untouched in this stage.
- Tracker: each task's key gets `devrounds task start` at dispatch, criteria checked with `commit:` evidence, then
  `devrounds task done` (controller). Apply the "Tracker mapping" edits before Task 1.

## Review Focus

1. An agent token calling approve or reject gets DR453; a human token of another tenant gets DR201 for the version;
   two concurrent approvals of one proposal leave exactly one active version and answer DR313 to the loser (never a raw
   23505). Tests in Task 2.
2. A block edited by hand, a block rendered from a proposed (never approved) version, a target file without its block,
   and a CRLF checkout of an untouched render: the first three fail with `docs_drift`, the last passes. Tests in Task 5.
3. The unified-diff parser on a rename with edits, a new file, a deleted file, `\ No newline at end of file`, CRLF
   lines, a binary file and a quoted path with spaces: added lines carry the right new-file line numbers, deleted files
   add nothing. Tests in Task 6.
4. A `pattern` rule with `unless` on the same line, `exclude` over `paths`, and a rule whose regex would match a
   removed line only: no violation in the last two. Tests in Task 6.
5. A check posted for a run of another project, a finished run, or a second time for the same run: DR201, DR312, DR312.
   Tests in Task 7.
6. A gate whose conventions check was green from the cache before a new version was approved must run it again (Global
   Constraints, cache). Test in Task 10.

## Calls made

Each by Claude under Guilherme's standing rule for DevRounds; the ones that change or add to the design say so.

1. **Two migrations** (adds): `convention_sets` lands with Task 2, `convention_checks` with Task 7, so Tasks 3-6 do
   not wait on the results table.
2. **`--diff` takes `-` or a path** (adds to call 10): the e2e feeds fixture diffs without a git repository.
3. **DR313 for deciding a version that is not proposed** (adds): approve/reject of an active, superseded, rejected or
   withdrawn version, and the loser of two concurrent approvals.
4. **No active version is DR201 kind `conventions`** for `check`, `render` and `show` (exit 3, class `environment` in
   the job type): a project adds the check to its gate only after version 1 is approved, so its absence is a setup
   error, not a pass. Cost if wrong: one flag to pass instead.
5. **`show --paths` selects by `paths`/`exclude`; a rule without `paths` applies everywhere** (judgment rules are often
   repo-wide). Output in agent mode: blocking rules first, then warn, then judgment; one line per rule
   (`key severity kind title`), `why` on the next line, cut at 16 KiB with the cursor.
6. **`verify` source key is `conventions:evidence:<rule key>`** (design call 13), opened through `POST /findings` with
   the missing excerpts as description and criterion `evidence restored or rule changed, with evidence`; exit codes as
   `report improvement --open-tasks` (each finding tried, first refusal's code).
7. **The version diff is by key** (adds): added, removed, changed items (fields that differ, by name), and target
   changes; `diff` prints removed and changed blocking rules first, since those are what an approver must not miss.
8. **DevRounds's AGENTS.md keeps its hand-written header, "Every session" and "Accepted P0 exceptions"**; "Never" and
   "Always" become the generated block (design call 16). The `agent-docs.test.ts` check keeps reading the whole file.
9. **Indicators count by the tenant's local day of `created_at`**, like gates; a cached check posts nothing and so
   counts nothing.
